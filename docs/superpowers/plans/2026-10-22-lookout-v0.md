# lookout V0 — Plan d'implémentation

> **Pour les agents d'exécution :** SOUS-COMPÉTENCE REQUISE : utiliser superpowers:subagent-driven-development (recommandé) ou superpowers:executing-plans pour exécuter ce plan tâche par tâche. Les étapes utilisent la syntaxe de cases à cocher (`- [ ]`).

**Objectif :** une application desktop (Mac + Windows) qui se connecte en SSH à plusieurs VPS, détecte automatiquement les projets Docker/Caddy, affiche santé et consommation, les logs, et permet de redémarrer des conteneurs avec confirmation.

**Architecture :** processus principal Electron (SSH, collecte, liste fixe de commandes, trousseau) + interface React/Tailwind isolée par `contextIsolation`, reliée par une API IPC typée. La collecte est faite de parseurs purs testés sur des fixtures ; la couche SSH est testée contre un faux serveur `ssh2` en processus.

**Stack :** TypeScript, Electron, electron-vite, React, Tailwind, Vitest + Testing Library, `ssh2`, `@napi-rs/keyring`, `i18next`/`react-i18next`, `zustand`, `electron-builder`. Graphiques : **Recharts** (SVG, testable sous jsdom avec largeur/hauteur fixes), enveloppé dans un composant `Sparkline` pour garder un style unique (courbe simple, sans axes ni grille).

**Spec :** `docs/superpowers/specs/2026-10-21-vps-desktop-manager-design.md` (à lire avec ce plan).

## Contraintes globales

- Electron + React + Tailwind + TypeScript, thème sombre, courbes simples uniquement ; Mac et Windows.
- SSH uniquement, **rien n'est installé sur le serveur** ; aucun appel à l'API GitHub ; aucune télémétrie ; seules connexions sortantes : SSH vers les serveurs de l'utilisateur, résolution DNS et sonde TLS vers ses propres domaines.
- Aucun secret dans les fichiers de l'app : passphrases/mots de passe dans le trousseau système ; jamais de clé privée copiée.
- Toute modification de la production exige une confirmation qui affiche la **commande exacte** exécutée.
- Liste fixe de commandes ; aucune chaîne libre construite à partir d'une saisie ; lectures de fichiers uniquement sur des chemins découverts.
- Anglais par défaut, traduction française dès le premier écran (i18n) ; README, CONTRIBUTING et commits en anglais.
- Licence MIT. Le **nom est provisoire** (`lookout`) : il ne doit apparaître que dans `src/shared/brand.ts`, `package.json` et la config `electron-builder`.
- Valeurs de départ : rafraîchissement 5 s (serveur affiché) et 45 s (autres) ; seuils orange CPU > 70 % ; tampon de logs 5 000 lignes ; Docker ≥ 20.10, Compose v2, démon classique (rootless/Podman hors V0).
- États : conteneur terminé avec code 0 = neutre ; rouge = échec de santé, redémarrage en boucle, code ≠ 0, ou arrêté alors que `restart: always|unless-stopped`.
- Reporté par la spec (« au mieux ») : `ProxyJump` est lu mais pas suivi en V0 (message clair).
- **Extensibilité (décision du porteur) :** les reverse proxies passent par une interface `ProxyProvider` (Caddy en Tâche 7, nginx en Tâche 19 ; Traefik, Apache et autres ajoutables plus tard sans toucher à la détection). Tout ce qui n'est pas géré reste listé dans `undetected`.

## Points de revue (cas que la spec sous-entend sans les tester)

1. Nom de conteneur/chemin avec métacaractères shell ou tiret initial (`a; rm -rf /`, `$(id)`, `--all`) : refusé par la liste fixe, jamais exécuté (Tâche 3).
2. Sortie vide, tronquée ou « permission denied » (Docker absent, démon arrêté, utilisateur hors groupe `docker`) : l'écran montre « Docker indisponible » avec la cause, pas un écran vide ni un plantage (Tâches 6, 9, 14).
3. Serveur injoignable, délai dépassé, empreinte d'hôte modifiée en cours de route : rouge + nouvelle tentative, et une empreinte changée **bloque** la connexion avant toute authentification (Tâche 4).
4. Projet sans conteneur (site statique), conteneur isolé sans Compose, Caddy absent ou API d'admin fermée : détection dégradée, jamais d'exception (Tâche 8).
5. Logs énormes, lignes très longues, séquences ANSI, `<script>` dans une ligne : l'affichage reste fluide, texte échappé, ANSI retiré, tampon plafonné (Tâche 16).
